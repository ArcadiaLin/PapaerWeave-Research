## 意图在评测中的三种用途

- **写者任务：** 每类意图给出写者要做的事和要写下的东西（有据层记录、产物）。
- **读者探针：** 题目按模板从意图实例化，金标准来自语料事实表（论文与代码，各带锚点），不来自任何一臂的库。
- **检索面：** 意图决定读者要从库里取什么、按什么条件取；这决定了哪些结构必须是字段或关系。
- 意图是工作负载，不是功能清单：不要求系统“支持”每类意图的全部推理，只要求库让读者取得完成它所需的信息与依据。

## 与 V2 的差别

- **代码库从“只记地址”变为证据。** V2 中 Code 只是资源实体，I6 只找地址，配置依据只从论文读。V3 中官方代码库是与论文正文并列的材料：可读、可作为锚点，按 commit 固定版本。
- **代码证据不只服务 I6。** 先导 q7 说明，I3 的可比性与 I5 的核查都可能只有代码能定：PatchTST 官方代码的测试 DataLoader 设 `drop_last=True`，TiDE 修正后重新评测，两篇论文同一格的差别由此而来；只读论文正文时，这一归属判断写错了。
- **执行与复现仍在库外。** 读代码、记配置、指出协议差异在库内；运行、复现、数值核验是外部执行者的发现，不入库。
- **每类意图对应产物类型与探针模板。** 模板编号与出题规范一致（T1–T18）。

## 六类意图

### I1 发现适合当前需求的工作与方法

- **需要的信息：** 方法候选、用途、前提、出处；相关不等于适用，方法不等于同名代码。
- **写者任务：** 按需求整理候选方法及其前提，写成 Generate。
- **产物：** Generate。
- **探针模板：** T9 身份（方法在别处以什么名字出现）、T15 跨写者可发现。
- **代码证据：** 无直接需求；方法是否有官方实现交给 I6。

### I2 理解方法的机制、条件与细节

- **需要的信息：** 机制、数据与资源要求、实验设置、原文位置；对象定义与某次具体使用不同。
- **写者任务：** 读论文，写下实验条件（look-back、切分、归一化等）与机制要点；需要综述时写 Summarize。
- **产物：** Summarize。
- **探针模板：** T2 单篇条件、T11 版本（库跟的是论文哪个版本）、T16 论文与代码一致。
- **代码证据：** 论文写的设置与官方脚本的默认值是否一致；论文没写的设置在代码中是什么。

### I3 组织实验结果并判断比较口径

- **需要的信息：** 被测对象、数据集、指标、结果、实验条件、结果来源（自己跑还是引用、引自谁）；同数据集不等于同口径。
- **写者任务：** 把论文结果写进排行榜；判断两行能否比较，写成 CompareSettings。
- **产物：** Leaderboard、CompareSettings。
- **探针模板：** T1 单格查值、T3 带条件的最优、T4 交集与计数、T6 集合差、T7 来源、T8 跨论文一致性、T12 历史状态、T13 覆盖、T18 协议差异的代码证据。
- **代码证据：** 数据切分、测试集加载、指标在归一化前后计算、基线是否套用公共代码库；这些解释同一格为何不同。

### I4 综合同一问题下的路线与发现

- **需要的信息：** 共同问题、各篇的回答、方法区别、具体发现与引用；共同认识不能覆盖来源差异。
- **写者任务：** 跨论文综合某一问题，写成 Summarize，引用实验记录与其他产物。
- **产物：** Summarize（可引用 Leaderboard、CompareSettings）。
- **探针模板：** T5 链式多跳、T4、T6。
- **代码证据：** 无直接需求；综合引用 I3 的可比性判断时间接用到。

### I5 核查主张的依据与成立范围

- **需要的信息：** 待核查的说法、相关主张、支持、限定或反驳的材料；已存判断不等于本次验证。
- **写者任务：** 核查一条主张，写成 Verify；与前人判断不同时保留前人的判断、另起一节。
- **产物：** Verify。
- **探针模板：** T10 主张核查、T8、T18。
- **代码证据：** 主张依赖的实验协议在代码中是否如论文所述；协议缺陷（如测试集丢样本）可作为限定或反驳的依据。

### I6 找到实现资源并判断能否作为实验起点

- **需要的信息：** 资源身份、地址出处、固定版本、配置、实现位置；论文声称公开与找到实现分开。
- **写者任务：** 找到方法的官方实现（论文给出的地址，或可靠出处），读代码，记下配置与关键组件的位置，写成 Generate。
- **产物：** Generate。
- **探针模板：** T14 资源可得（地址与出处）、T16、T17 实现定位。
- **代码证据：** 本意图的主体。仓库不可得、与论文不一致，如实记下，本身就是答案。

## 代码证据的边界

- **库内：**
  - 代码仓库作为 Code 的材料（路径 + commit），换 commit 即新版本，与论文换材料同理〔待商定〕；
  - 锚点可以指向代码文件的行，`read_evidence` 可以读代码〔待商定〕；
  - 写者从代码中读出的配置、协议差异与实现位置，作为有据层记录或产物内容写入。
- **库外：** 运行、复现、数值核验、性能比较的执行结果。
- **评测侧（不依赖系统改动）：** 语料事实表含代码事实，金标准可引用代码锚点；仓库按“论文所用版本发布当天或之前的最后一个 commit”固定。
- **未改模型之前：** T16–T18 在“读者只读库”条件下对各臂都基本答不了，只放在“另能读原文与代码”的辅助条件中。
