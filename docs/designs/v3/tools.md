# 工具 V3

> **状态：** 草案（2026-10-16），待用户审阅；未实现。本文列出 agent 经 MCP 使用的工具（V2 称"算子"）。数据模型见 [数据模型 V3](./data_model.md)。先列骨架，细节逐步补充。
>
> 标 **〔待确认〕** 的是本稿提出、尚未与用户确认的改动。

## 总览：两组工具

| 组 | 工具 | 写库 |
| --- | --- | --- |
| 知识访问 | `search`、`get`、`traverse`、`read_evidence` | 否 |
| 版本管理 | `commit`、`fetch_artifact`、`check_in`、`log`、`show`、`diff`、`as_of` | `commit`、`check_in` 各产生一个提交 |

带 `[]` 的是列表参数。工具不调用 LLM；引用只接受已有的 id。

- **知识访问**：只读当前状态
  - `search`：一个检索覆盖全部节点与带说明的关系 〔待确认〕
    - `query` 必填：名称、标识或描述性文字，一个字符串
    - `kind[]`：只在这些 kind 中找，可以是产物类型（如 `Leaderboard`）；不给时查全部
    - `topn`：返回条数，默认 10
    - 返回：每条结果渲染成一行文字，涉及的对象写作 `名称[id]`；`match` 标明命中方式：`identifier`、`name`、`alias`、`similar`
    - 证据节点的结果行附带用到它的产物（id 与类型），不参与排序 〔待确认〕
    - 说明末尾附会话开始时的库总览，见下节
  - `get`：给 id，返回详细信息（取代 `resolve`）〔待确认〕
    - `ids[]` 必填
    - 返回：全部字段、渲染成句子的出边、各类入边的条数、用到它的产物
  - `traverse`：沿关系走，表达结构条件
    - `start[]` 必填：起点 id
    - `path`：0–3 跳，每跳给出关系、方向与条件
    - `continuation`：翻页
  - `read_evidence`：读原文行或产物文档行
    - `source_refs[]` 必填：写作 `<论文或产物 id>::<章节>::<起>:<止>`
    - `at`：按某次提交时的材料解析
- **版本管理**：围绕提交
  - `commit`：提交 graph-doc，改证据节点与关系
    - `doc_file` 或 `doc` 必填：graph-doc 文件路径，或直接给出文本
    - `message` 必填：一行说明
    - `source`：知识来源，不给时记为会话
    - `apply`：`false` 只预演
  - `fetch_artifact`：把产物检出到工作目录
    - `artifact[]` 必填：产物 id
    - `at`：取旧版本，只读
  - `check_in`：检入编辑后的产物文档，或新建产物
    - `artifact_doc[]` 必填：文档路径，多份一起成功或一起失败
    - `update_abstract` 必填：改了什么、为什么
    - `confirm`：`true` 才写入，不给时只检查
    - `reason`：改动他人写的行时必填
  - `log`：列出提交历史，可按节点、写者、来源、时间过滤
  - `show`：一次提交改了什么、依据什么
  - `diff`：两个提交之间的净差异
  - `as_of`：按 id 读某次提交之后的旧状态

## 会话开始时的总览

让写者不必主动去想，就知道库里已有哪些前人结果，作用相当于 files + Git 组的 `ls artifacts/`。

- 位置：`search` 的工具说明末尾
  - MCP 服务每个连接新启动一次，启动时按当前库生成
  - pi 以 direct 方式列出工具时，工具说明每轮都在模型面前；服务的 `instructions` 模型看不到
- 内容：各产物类型的份数，最近几份的标题与 id；Skill 注明已放在 `.agents/skills/`
- 长度：几百字以内，其余用 `search` 加 `kind` 查
- 时效：会话开始时的快照；写者轮流运行，会话中只多出自己写的
