# 工具 V3

> **状态：** 已实现（2026-10-16 夜，`system/`，提交 `1502e44` 起），在 [V3 RPC 实验室](../../experiments/2026-10-17-v3-rpc-lab.md) 中边测边改；待用户审阅。本文列出 agent 经 MCP 使用的工具（V2 称"算子"）。数据模型见 [数据模型 V3](./data_model.md)。给模型看的全部文字在 `system/src/paperweave/mcp/server.yml`，本文只记结构与理由。
>
> 标 **〔待确认〕** 的是实现中自行决定、尚未与用户确认的改动；标〔已确认 2026-10-17〕的已由用户确认。

## 总览：两组工具

| 组 | 工具 | 写库 |
| --- | --- | --- |
| 知识访问 | `search`、`get`、`traverse`、`read_evidence` | 否 |
| 版本管理 | `checkout`、`commit`、`log`、`show`、`diff`、`as_of` | `commit`（graph-doc 与产物文档各产生一个提交） |

工具名全部小写；在 pi 中显示为 `mcp__PaperWeave__<名>`。带 `[]` 的是列表参数。工具不调用 LLM；引用只接受已有的 id。写入者的身份由服务端登录给出（`PAPERWEAVE_USER`），不是参数。

读取工具（`search`、`get`、`traverse`）返回**带注释的 YAML**：注释（`#` 之后）给出 id 的名称与锚点所在的章节，`_` 开头的字段只读。去掉注释仍是合法的 graph-doc 片段：`get` 的节点原样贴进 `set` 是 noop。

## 知识访问

- `search(query, kind[]?, paper[]?, topn?: 10)`：一个检索覆盖全部节点、产物与带说明的关系。
  - 实现：模型节点与产物都带公共 Label `Searchable`（系统写入，agent 看不到）。Neo4j 的向量索引只能挂在一个 Label 上，有了它，全文、向量各一个索引就覆盖全部类别；Cypher 中也用它区分模型节点与名称键、材料、提交记录等内部节点。
  - 精确命中在前，标 `_match`：`id`、外部标识（`arxiv:2205.13504` 或不带命名空间的 arXiv 号）、名称或别名（不分大小写）。
  - 其余按四路 RRF（节点全文、节点向量、关系全文、关系向量；`RRF_K=20`，每路取 30）排序。关系命中挂在起点下，只列命中的那几条关系。
  - `kind` 可以是 kind、类别（Entity / Concept / Content）、产物类型或关系类型。不指定产物类型时，结果中至多混入 3 份产物，其余计数在开头的注释中。
  - 每条结果是紧凑投影：kind、名称或描述摘录、论文、锚点、主要出边、入边计数。
  - 说明末尾附会话开始时的库总览（下节）。
  - 〔已确认 2026-10-17〕不再分页，不再有 `where`。按产物身份查找（V2 的 `where.key`）删除：写重复身份的产物时 `commit` 报 `identity` 并给出已有 id。
- `get(ids[], offset?: 0, limit?: 30)`：全部字段与出边，形状与 graph-doc 中 `set`（字段）和 `create`（边）下写的相同。
  - 只读字段：`_formed_by`、`_formed_at`、`_edges_in`（各类入边的条数）、`_supported_by` / `_opposed_by` / `_used_by`、有据层记录的 `_revised`（最近一次修订的提交、作者、理由、锚点）、锚点写在论文旧材料上时的 `_anchor_version`、产物的 `_stale`。
  - 〔已确认 2026-10-17〕产物只给元信息：类型、标题、摘要、`_stale`，以及 `_uses`（`USED` 边按在文档中的位置分组，如 `method`、`paper`、`dataset`，与节点的出边一样分页），`_document` 提示用 `checkout` 取成文件。正文不在 `get` 中：要读全文的人与要改的人走同一条路，读完要改不必再取一次。
  - 一次至多 20 个 id。
  - 〔已确认 2026-10-17〕分页，与 pi 的 `read` 同一用法：每种出边按终点 id 排序，只列第 `offset` 起的 `limit` 条；还有剩余时，结尾的注释写明 `[<id> <关系>: showing 1-30 of 124]` 与 `[Use offset=30 with ids=[…] to continue.]`。返回超过 16 KB 时按整节点截短，剩下的 id 也在结尾给出。同样的参数与库状态返回同样的一页；分页的节点贴回 `set` 也安全（`set` 只改写列出的边）。`checkout` 不分页。
  - 预算 16 KB 的依据：pi 把超过约 20 KB 的 MCP 返回转存为临时文件，在字节处硬切；12 轮中这样溢出 8 次，模型只有 4 次去翻，且多半只翻一部分。
- `traverse(start[], path?, limit?: 30, offset?: 0)`：沿关系走，表达结构条件与穷举。
  - `path` 是 0–3 跳，每跳 `{rel, dir?: out | in | both, kind?}`；`rel` 可以是列表，含系统关系 `FROM`（Content → 论文）与 `USED`（产物 → 用到的节点）。
  - 结果是最后一跳到达的节点，按 id 排序，各带 `_via`：上一步从哪些节点、经哪条边到达，带边上的属性。总数在开头的注释中。
  - 〔已确认 2026-10-17〕不再有 `where`、`edge`、`depth`。分页改为与 `get` 相同的用法：到达的节点按 id 排序，从第 `offset` 个起最多 `limit` 个，超过 16 KB 时提前停下，结尾给出 `[Showing 1-11 of 23 nodes. Use offset=11 to continue.]`。p2 中溢出的那次遍历（23 个实验，20 KB）现在分两页。
- `read_evidence(source_refs[], at?)`：读论文或产物文档中的行。
  - 引用写作 `<论文或产物 id>::<起>:<止>`；中间带章节（V2 写法）也接受，只作提示。返回中补上所在章节。
  - 单条引用至多 400 行。

## 版本管理

- `checkout(ids[]?, new[]?)`：把要写的东西放进工作目录，不改动库。
  - `ids` 中的产物：取出当前版本的文档（头部带 `id`、`base`；V2 的 `fetch_artifact`）。〔已确认 2026-10-17〕读和改都走这一步：文件放进工作目录，agent 用自己的读文件工具读（翻页由它做），要改就改这个文件再 `commit`。返回只有路径、版本、最近一次编辑与 `since_your_last_edit` 的一句话；编辑提示与类型的附注写进旁边的 `<文档名>.notes.yaml`，返回中给出路径与各项条数。ETTh1 排行榜的返回由 16.2 KB 降到 686 字节（RPC 第 11 轮中，读者为读表 `checkout`，16 KB 的提示被 pi 截断）。
  - `ids` 中的证据节点：写成一份 graph-doc，节点在 `set` 下（即 `get` 的投影），改值即修改。
  - `new` 中的 kind：一份空白 graph-doc 模板，每个 kind 一个 `$` 节点，字段与能连的关系都带注释；模板由数据模型登记表生成。产物类型（Leaderboard、Generate）给出该类型的空白文档。
  - 〔已确认 2026-10-17〕不再支持取旧版本（V2 的 `at`）：旧状态用 `as_of`，旧文档行用 `read_evidence at`。
- `commit(files[], message, reason?, dry_run?)`：提交工作目录中的文件。
  - 以 `graph-doc:` 开头的 YAML 是 graph-doc（一次至多一份：`$` 名只在一份文件内有效），其余按头部的 `type` 是产物文档。
  - 先对全部文件做检查，任何一份有阻塞项时都不写；位置换算成 `<文件>:<行号> (<文档中的路径>)`。通过后 graph-doc 一个提交、产物文档一个提交。
  - 错误报告要短（RPC 第 2 轮：20 KB 的返回被 pi 截断，写者只能到临时文件里翻找）：规则、消息与改法都相同的错误只报一次，`at` 列出各处；查重候选一行一个；方向写反时给出另一端的写法；只检查本次写入或改动的边。
  - dry run 与提交结果的计数同一口径：只算证据节点与关系，不算名称键与材料。
  - `message` 是提交说明，也是产物的 `update_abstract`；改动他人写的产物行时要 `reason`。
  - 〔已确认 2026-10-17〕默认直接写入（V2 的 CheckIn 默认只检查），`dry_run: true` 只检查。两种方式的检查相同（含查重），有阻塞项时都不写；`dry_run` 只是检查通过后也不写。
  - 提交后补算检索用的派生字段（`search_text`、`embedding`），失败只提示，下次提交重算。
  - 涉及 Experiment 时返回 `related_artifacts`：其评测数据集上的 Leaderboard，以及还没有 Leaderboard 的数据集。
  - 〔已确认 2026-10-17〕返回 `affected_artifacts`：因本次提交新出现可能过期原因的产物，每项给出产物 id、标题、类型与原因（如 `exp_0015 revised`、`paper_0002 uncovered (exp_0002)`、`art_0001#<行键> superseded`），至多列 5 个，其余在 `more` 中，另附一句说明：是否更新由写者决定。只是信息，不阻塞，也算不出时只记警告。
    - 判断全部复用 `_stale`：提交前对候选产物算一次，提交后再算一次，只报新出现的原因（按引用与原因比较），之前已经报过的不再重复。
    - 候选：graph-doc 提交是 `USED` 指向本次触及（含删除）的节点的产物、本次触及的 Experiment 所用数据集上的 Leaderboard；产物提交是引用了本次更新的产物的产物；两者都再沿 `USED` 反向取用到它们的产物（`stale input` 由此传递）。一次提交里两部分各报各的，分别在 `graph_doc` 与 `artifacts` 下。
    - 理由：`_stale` 只在读取时计算，改证据的写者看不到它让哪些产物过期，要等下一个读到产物的人。这是视图失效在写入一侧的补全。RPC 第 17 轮（m4）中，任务只要求补全一条实验记录，写者看到 `art_0001 … exp_0015 revised` 后主动取出排行榜，把 5 行改指正确的方法。
    - 已知的粗糙处：被引用的产物出了新版本，下游一律报 `superseded`，即使所引的行没有变；沿用 `_stale` 按版本判断的规则，不做行级比较。
  - 〔已确认 2026-10-17〕产物检入的返回带类型的附注；随表变长的逐条附注只展开本次新增与修改的行所涉及的（Leaderboard 的多值单元格），其余只给条数，全部明细由 `checkout` 写进 notes 文件。m4 中 ETTh1 排行榜检入时附注由 7.3 KB 降到 0.2 KB。
- 产物的 `_stale`（`get`、`search` 中给出，读取时计算）：V2 的各项原因之外，Leaderboard 另有隐含输入。表中论文里使用表头数据集的 Experiment 被修订时报 `revised`；库中有使用该数据集、但论文不在表中的 Experiment 时报 `uncovered`。有意不收的论文写进 “Papers covered” 并说明原因，提示即消失。RPC 第 9 轮中，下一位写者正是据此把漏掉的论文补进了表。
  - 〔待议，未实现〕两处收紧：`uncovered` 只算 `ON_TASK` 与表头 `task` 一致的实验；`revised` 只算锚点与表中所引论文行重叠的实验（现在表中论文里用到该数据集的实验都算，改一个消融实验也会让整张表报 `revised`）。单变量、多变量这类设置不在实验上结构化，不做过滤，交给写者在 “Papers covered” 中说明。
- 参数修复（不提示给 agent，只记日志）：列表参数收到逗号分隔的字符串时切开；对象或数组参数收到 YAML 行内写法（键不加引号）时按 graph-doc 的 YAML 规则解析。
- `log`、`show`、`diff`、`as_of`：与 V2 相同，视图换成 V3 的 `get` 形状；由别的对象决定的只读字段（入边计数等）不计入变化。

## 会话开始时的总览

让写者不必主动去想，就知道库里已有哪些前人结果，作用相当于 files + Git 组的 `ls artifacts/`。

- 位置：`search` 的工具说明末尾。MCP 服务每个连接新启动一次，启动时按当前库生成；pi 以 direct 方式列出工具时，工具说明每轮都在模型面前，服务的 `instructions` 模型看不到。
- 内容：各 kind 的节点数；至多 20 篇论文（id 与名称）；各产物类型的份数与最近 3 份的标题与 id。空库时只说库是空的。
- 时效：会话开始时的快照；写者轮流运行，会话中只多出自己写的。

## 实现结构

`model ← store ← draft、commit ← query ← artifact ← operators、interfaces ← tools ← mcp、cli`，由 `system/tests/test_layers.py` 检查（AST）。

- `model/schema.py`：kind 与关系的登记表；`model/templates.py`：由登记表生成空白模板与工具说明中的词表。
- `query/search.py`：检索；`query/view.py`、`query/render.py`：投影与带注释的 YAML；`query/read.py`：读出投影；`query/dedup.py`：写入时的查重（注入 `commit`）；`query/overview.py`：总览。
- `store/derived.py`：派生字段（检索文本与向量），每次提交后补算，不受版本管理。
- `operators/db/`：一工具一文件。

## 待定

- 〔已确认 2026-10-17〕`search` 不设向量阈值，也不分页：结果按相关度排序，超出 20 KB 时由 pi 的临时文件兜底，截掉的是低相关的尾部。
- 〔已确认 2026-10-17〕检索用的派生字段按提交增量重算：本次触及的节点与它们的一层邻居（`related` 里有邻居的名称），以及端点在触及节点中的带描述的边；只写回变了的文本，只为变了的向量文本补算向量。不给范围时全量重算（建库、修复用）。lab 库上一次新论文的提交（触及 55 个节点）重算 108 个，一次小修正（触及 1 个）重算 5 个。
- 〔已确认 2026-10-17〕产物的检索文本是标题、摘要与它用到的节点的名称（`USED` 的终点，至多 40 个），只放在产物一侧：节点的 `related` 不放产物标题，免得 ETTh1 这类热门节点的检索文本被产物挤满、检索结果被带偏。从节点找产物用 `_used_by`、`traverse` 沿 `USED` 反向走与 `related_artifacts`。
- 产物之间的语义关系（取代、相左、重复）：暂不加。依赖已由产物 → 产物的 `USED` 表达（引用另一份产物的行），过期沿它传递；重复由身份键拦下；相左的判断从它们共同用到的节点沿 `USED` 反向找到。等工作负载需要时再定。
