# 草稿文件：大块内容经文件交给算子

状态：已同意（2026-10-11），已实现（`experiments/e09/src/e09/draft.py`，Git `a8ec86f`）。2026-10-12 随算子契约修订：

- Extract 与 MatrixConstruct 已从算子集合中去掉（[算子契约](./operators.md) §8），它们的 CSV 草稿随之作废，代码随旧算子一起移除；
- 本文的原则推广到新的产物算子：产物文档就是写者工作目录里的一份文件，经 `FetchArtifact` 取出、编辑后按路径检入（[算子契约](./operators.md) §3.6、§4.1）；
- Commit 的 `doc_file` 不变。

旧版见 Git `a8ec86f`。

## 1. 问题

T1 先导 pilot-1（`~/t1-runs/pilot-1`，停于 A3 第 5 个会话）暴露两个问题。

**写入成本中近一半是重交。** A3 全部会话的输出 token 按写入结果分：

| 去向 | 占比 |
| --- | --- |
| 被拒绝或被拦下、随后整份重交的写入调用 | 45% |
| 成功的写入 | 39% |
| 读取等其他工具 | 11% |
| 预演通过（之后原样再交） | 4% |
| 最终回复 | 1% |

原因是写入内容全部放在工具参数里：

- Extract 的每一行都是一个带键名的 JSON 对象，约 70 token。168 行的主表约 1.15 万 token。
- 校验发现几行引用格式不对，写者也只能把整份表重新生成一遍：同一份 168 行的表交了 3 次。
- Commit 的工具描述要求先预演、再带 `apply: true` 原样重交，一份 4000 token 的文档至少要生成两遍。

**大参数被客户端超时截断。** sglang 的 `qwen3_coder` 解析器把一个工具参数整段生成完才发出，期间连接上没有任何字节。pi 的空闲超时 `httpIdleTimeoutMs` 默认为 300 秒，到点即断开（`terminated`）。按约 80 到 110 token/秒的速度，单个参数超过约 2.5 万 token 就会失败。A0 一次写出整篇论文笔记时失败了 5 次。这一点在 T1 运行框架里单独修复（§9），本设计只保证工具参数不再变大。

## 2. 原则

**大块内容走文件，参数只放路径与少量声明。**

- 写者用自己的文件工具（pi 的 `write`、`edit`）在工作目录里写文件；调用算子时只传路径。
- 服务端读入并校验。被拒时，报错指出文件与行号，写者就地修改那几行后，用同样的短参数再交。
- 通过后登记。Commit 的 graph-doc 是草稿：服务端按解析后的内容写库，之后文件再改也不影响库。产物文档按原样保存为新版本（去掉 `id`、`base` 两行），写者的排版保留（[算子契约](./operators.md) §4.1）。

2026-10-11 的版本中，原则是“草稿是写者的，产物是服务端的”：产物由服务端从解析后的内容重新生成。产物改为可共同编辑的文档之后，产物文档本身就是写者编辑的文件，这一条不再成立。

**这不改变写入契约。** 校验规则、查重退回写者、有据层修订、`USED` 与 `_stale` 都不变。变的只是内容进入服务端的通道。

**引导只经工具描述与工具返回。** 符合"通用 Agent 经 MCP 使用系统"的设定：不改系统提示，不加专用工具。

## 3. 接口

| 算子 | 参数 | 内容 | 状态 |
| --- | --- | --- | --- |
| Commit | `doc_file`：graph-doc YAML 的路径 | 与 `doc` 参数相同；小文档仍可直接写 `doc`，二者同时给出时拒绝（`format`） | 已实现 |
| 产物算子（Leaderboard、CompareSettings、Verify、Summarize、Generate） | `artifact_doc`：Markdown 文档的路径或路径列表 | 头部 YAML 加正文；只能经文件提交 | 待实现 |

工具描述写明：graph-doc 较长时用文件。

2026-10-11 版的 Extract 与 MatrixConstruct 用 `payload_file`（CSV 草稿）。它们已被去掉，CSV 格式与“只给 `params` 时返回模板”的做法随之作废。产物的格式改由种子示例与已有的产物示范：写者 fetch 一份已有的产物，照着写（[算子契约](./operators.md) §1.3）。

## 4. 报错带行号

现有校验报告的位置形如 `nodes.$exp.FROM[0].locators`。内容来自文件时，服务端把这些位置换算成文件位置：

```yaml
status: rejected
errors:
- rule: reference
  at: artifacts/ETTh1 multivariate long-term forecasting.md:47 (source)
  msg: source "material_fa42…::line::291:291" is not <material>::<section>::<start>:<end>
```

- YAML：用 YAML 解析器记下的节点位置，把结构路径换算成行号，换算不到时退回结构路径。
- 产物文档：表格的行与正文的行直接给出文件中的行号；头部字段按 YAML 换算。
- 一次列出全部错误，不在第一处出错时就停止。

工具描述给出固定的工作流程：写文件（或 fetch 后编辑）；用路径调用；被拒时只改报错列出的行，再用同样的参数调用。

## 5. 定稿与溯源

- **Commit：提交即定稿。** 库按解析后的 graph-doc 写入，之后草稿再改不影响库。
- **产物：检入即一个版本。** 检入的文档原样保存为新版本的 Material（材料根目录的 `artifacts/`）。写者工作目录里的那份文件之后再改，不影响已登记的版本；要改就再检入一次，得到下一个版本。
- **记下提交的内容。** 提交的 `input` 记录调用参数加上文件原文，`meta.draft` 记录路径与 SHA-256。评估写者行为时，可以看到每次交上来的完整内容（工作原则 4）。

## 6. 路径

- 只接受写者工作目录内的路径：相对路径相对于工作目录；绝对路径必须落在工作目录之内。规范化后（解析 `..` 与符号链接）仍须在工作目录内，否则拒绝（`format`）。
- 不接受材料根目录下的路径。写者交的是自己工作目录里的文件，不是已登记的材料。
- **工作目录由服务端决定**，写者无法自行声明：
  - 设置了 `E09_WORKDIR` 时用它（T1：写者工作目录在宿主机上的路径）。`E09_WORKDIR_ALIAS` 给出写者看到的同一目录（T1 沙箱中为 `/work`），以这个前缀开头的绝对路径按它换算。
  - 未设置时，用 MCP 服务进程的当前目录。pi 是否在工作区中启动 MCP 服务，实现时核实；不是的话，`make workspace` 生成的 MCP 登记里要写入 `E09_WORKDIR`。
- 单个文件不超过 2 MB，超过时拒绝。
- `FetchArtifact` 也写到这个工作目录（`./artifacts/`），路径规则相同。

## 7. Commit：一次调用完成

现有实现中，`apply: true` 本来就会先预演；有阻塞项时返回 graph-plan、不写入，没有时直接提交。"先预演、再原样重交"只是工具描述规定的流程。改为：

- MCP 中 Commit 的 `apply` 默认值改为 `true`。工具描述写明：直接交；被拦下（`blocked`）就按报错修改草稿后再交；只想预览时传 `apply: false`。
- 查重候选、修订要求等阻塞项照常在写入之前退回写者，写入时的裁决仍由写者做出。
- 命令行（`python -m e09`）的默认值不变，仍需显式 `--apply`。

产物算子与此不同：不带 `confirm` 时只校验（[算子契约](./operators.md) §4.1）。原因是产物的校验有警告（如数字不在所引的行中），警告应在写入前给出，否则为了改一个笔误要多出一个版本；Commit 只有阻塞项，没有阻塞时直接提交没有损失。

## 8. T1 运行框架的配套修复（不属于系统设计，一并记录）

- 沙箱内 pi 的设置加入 `httpIdleTimeoutMs: 1800000`，写入实验配置留档。
- MCP 服务的启动环境加入 `E09_WORKDIR`（写者工作目录在宿主机上的路径）与 `E09_WORKDIR_ALIAS=/work`。
- A0 会话结束后，记录笔记库中未提交的改动清单（写入 `sessions.jsonl`），然后丢弃这些改动，使两组对称：A3 中未经 Commit 的内容不进库；A0 中未经 git commit 的内容也不留给下一个写者。
- `sessions.jsonl` 增加每个会话的请求出错次数（`stopReason: error`）。会话前后的库版本已有记录，库没有变化的会话因此能直接看出来。

## 9. 验证

2026-10-11 版的单元测试与冒烟测试针对 CSV 草稿与 Commit 的一次调用。CSV 部分随旧算子作废；Commit 的部分仍然有效：

- graph-doc 文件解析后，与直接写在参数里的等价内容得到相同的结果；
- 报错行号的换算；
- 路径规则：越出工作目录、指向材料目录、符号链接越界、文件过大都被拒绝；
- Commit 的 `apply` 默认为 `true` 时，有阻塞项不写入，没有则提交。

产物文档的检入另随产物算子测试（[算子契约](./operators.md) §9）。
