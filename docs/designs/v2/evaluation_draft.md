## 1. 评测要回答的问题

### 1.1 主场与边界

最强的反驳是：**一个 Agent 用 markdown 文件加 git 就够了。** 在单个 Agent、单个项目、几十篇论文的场景里，这个反驳大概率成立；即使数据库有优势，也可能抵不过构建成本。评测不把主场设在这里，但把它作为边界条件如实报告。

数据库思路站得住的场景是：**许多互不协调的 Agent 或 session，长期往同一个共享库里写入，也从中读取；读者往往不在写入现场。** 在这种场景下，无约束的积累预计会出现以下退化。写侧：

- **重复与误合并（C1）：** 同一个对象被不同写者写成多个实体，或者不同对象被并成一个；共同产物也会重演这个问题，同一张结果表被几个写者各建一份；
- **悬空（C2）：** 引用指向不存在或已被改动的对象，产物缺少条件与输入，复查不了；
- **未察觉的冲突与无理由的改动（C3）：** 不同写者对同一结果给出不同读法；后写的改了先写的，却没有理由，读者也不知道；
- **过时（C3）：** 产物所依据的材料或记录已经修订，却没有人知道它需要复检；
- **知识流失：** 先前正确的内容，后来被写坏或丢掉。

读侧：

- **找不到（C5）：** 写者按自己的目的、措辞和粒度存放内容，换一个目的的读者找不到。

下游读者拿到的答案会因此出错，而且错得不显眼。

### 1.2 三个命题

| 命题 | 内容 | 怎样算被证伪 |
| --- | --- | --- |
| **E1 完整性（主结果）** | 写者增多时，A3 的库健康度与下游正确率的损失明显小于各对照组 | 在可负担的规模内，A3 的多写者代价 $\Delta_{\text{A3}}$ 不显著小于 $\Delta_{\text{A0}}$（§4.2） |
| **E2 充分性** | 库中整理出的内容足以支撑研究意图，读者不必回读论文；按意图说明哪些能、哪些不能 | `store_only` 读者的正确率远低于 `with_papers`，且差距不随积累缩小 |
| **E3 对等** | 作为一种 memory，答题效果不逊于 agent memory 系统；构建成本前移，并在使用者之间摊销 | 低写者数时 A3 的下游正确率比 A4 差超过预先声明的阈值 $\delta$ |

另有系统开销与可扩展性（§7），不作为命题，但必须报告。

**[已商定]** E1 与 E2 必须一起报告：一个什么都不存的库永远不会退化，“不退化”本身可以被钻空子，充分性是退化实验有意义的前提。

**[已商定]** 不去卷 memory 的性能：E3 只主张非劣效，不主张超越。

### 1.3 论文主张与证据

每条要写进论文的主张，都要有对应的实验来支撑。没有实验支撑的主张，就从文中删掉。

| 主张 | 证据 | 位置 |
| --- | --- | --- |
| 写者增多时，库的退化明显慢于基于文件、图库和 agent memory 的对照组 | E1：$\Delta_{\text{arm}}$ 的组间比较；M1–M11 | §4 |
| 实体解析、共同编辑的产物与写入时的发现提示维持了库的完整性 | 三项消融 | §3.2、§4 |
| 有据层带完整历史地修订，解释层的判断带来源并存 | 有据层忠实度与冲突检出；解释层分歧保留率与可见率 | §4.3 |
| 外部锚点越弱，身份越难收敛 | 重复率按对象类型拆开 | §4.3 |
| 整理出的内容足以支撑意图（按意图说明边界） | E2：$\mathrm{Acc}_{\text{store\_only}} / \mathrm{Acc}_{\text{with\_papers}}$；与 A1 对照 | §5 |
| 别人为其他目的写下的内容，读者也能找到（C5） | 跨意图探针的找到率；采用率 M11 | §4.3、§5 |
| 作为 memory 不吃亏，成本可摊销 | E3：对 A4 的非劣效检验；成本账本 | §6 |

| 以意图为根的工作负载 | 写者背景与探针由 I1–I6 生成，并随论文公开 | §2 |

### 1.4 评测原则

- **先评存储层的支持能力。** 下游任务分数是应用证据，不是唯一的度量。正确率、交互与执行成本、可扩展性和维护行为都要报告。
- **能力对比要可操作。** 区分原生支持、经组合支持、需要外部推理才能支持三种情况。特性表本身不构成证据。
- **宣称与核验分离。** 论文的宣称、仓库中的观察、运行成功和实验复现是不同的发现；证据不足时保留不确定性。
- **公平对照。** 各组访问同样的材料，使用同一个通用 Agent（默认配置的 pi）、同一个模型和同样的预算。评测审计绕过 PaperWeave 直接读源材料的行为，但不禁止。
- **主指标跨组可比。** 跨组比较以下游探针与知识流失率为准，其余库健康度作为诊断。探针正确率混有读者能力、模型记忆与绕过行为，必须配合闭卷下限、神谕上限与逐题归因报告（§4.3）。
- **不拿自己的校验考别人。** A3 在写入时已经执行的检查（如出处格式、id 存在、数字在所引行中），只用来比较 A3 与它的消融、A2、A0，回答“去掉校验会怎样”，不作为 A3 胜过对照组的证据。E1 的证据来自系统不检查的项（§4.4）。
- **先冻结后实验。** 算子集合与种子先冻结，再写正式探针；写者背景、探针、金标准、rubric 和筛选规则在正式实验前冻结，不按正式结果挑题。负载要包含复用有利、收益不明显和可能有害的任务。
- **主张与负载对齐。** 主张只针对多写者、跨论文、跨 session、条件敏感的负载。在通用单轮问答上与 RAG 打平，不构成反驳。产物算子是按这个工作负载设计的，论文中如实写明：换工作负载要换算子与种子。
- **评测材料公开。** 任务定义、探针、金标准、rubric 和运行轨迹随论文公开。
- **评测代码不依赖被测系统。** 评测框架不导入系统的代码，只经外部可见的接口驱动系统、读取结果；测量用自己的解析器，读冻结的快照（§10.1）。

## 2. 工作负载：写者、起点、事件与探针

### 2.1 写者：伪用户

**[已商定]**

- **写入顺序：** 论文按入库顺序进入，每篇随机分给一个伪用户（同篇重叠时分给两个，§4.2），由他们自行维护库。随机分配用固定的种子。
- **伪用户的设定：** 每个伪用户有固定的身份（git 作者、`formed_by`）与一段长期的工作背景，对应一个意图，例如：
  - “你在做一个基准对比项目”（I3）；
  - “你在研究这些方法为什么有效”（I2）；
  - “你在核查论文中的主张”（I5）；
  - “你在为新项目挑选方法”（I1）。

  每次会话都是全新的上下文，只有身份与背景跨会话保持。
- **任务提示不提共同产物：** 只说“把这篇论文加入你的工作所用的知识库”。写者是否自己去找、去维护共同的表，本身就是一个观测量（采用率 M11）。
- **写者之间：** 没有共同的计划，也不互相通信；唯一的联系是共享库。
- **写者轮流执行。** 同一时刻只有一个写者在提交，事务级并发不在贡献范围内。要测的退化来自语义层面。
- **只走直写路径：** 写者经 `Commit` 与产物算子写入共享库。Fork / Merge 不在本轮范围内（§9）。

### 2.2 起点与种子

**[已商定]**

- 起点只有论文原文（固定版本的 `Material`）与外部标识。有据层与解释层都由写者构建，不预设权威快照。
- 种子在各组之间相同：种子论文（时序预测为 Informer、SCINet）及其入库内容，以及每类产物至少一份示例。其中种子 Leaderboard 只含种子论文的行，覆盖语料中的主要数据集，并包含难写的行（如 look-back 写成说明文字）。
- **A0 也拿到这些种子**，作为仓库里的 Markdown 文件，但不附任何“要求统一维护”的提示。A0 不拿 schema：统一的格式是 A3 的机制之一。
- 种子不能与金标准重合，探针也要避开种子论文。
- Wikidata、OpenAlex 等只作为标识命名空间，不作为起点快照。

### 2.3 注入事件

时间线上预先写定若干事件。事件对写者不可见，在指定的检查点发生。

| 事件 | 做法 | 检查什么 | 所在层 |
| --- | --- | --- | --- |
| 读错后修订 | 某写者的一条记录或一行结果含一个错误数值，之后由另一写者对照原文锚点修订 | 修订是否附锚点与理由；依赖它的产物是否被标为过时；旧值能否读回 | 有据层、共同产物 |
| 撤回 | 撤回一篇论文或一条记录（删除变更集或 `revert`）；解释层写一条 `OPPOSES` | 影响范围查询的正确率与误报 | 两层 |
| 材料变更 | 固定一份源材料的新版本，例如 arXiv v2 改了数值（pilot-2 的 FiLM v3→v4） | 产物的 `superseded` 提示；依据它的行是否被更新 | 两层 |
| 写者分歧 | 两个写者对同一对象写出不同内容（同篇重叠自然产生） | 有据层：是否被检出并回到锚点修订；解释层：是否并存、各带来源、读者是否看得到 | 两层 |
| 回看 | 查询某份产物在早先某个版本时的内容与依据 | 历史读取的正确性（`FetchArtifact(at)`、`AsOf`） | — |

分歧与修订事件优先取材于真实历史，例如复现不一致、arXiv 版本差异、勘误，以及银标准与原文不一致的条目（§8.2）；不够时再人工构造。各对照组经历同样的事件。A0 可以用 git 历史和自己维护的笔记应对，比较的是应对的正确率和代价。

### 2.4 读者探针

**[已商定]** 探针按 I1–I6 的任务形式设计，有公开任务作为依据。探针由一个固定的读者 Agent 执行，读者与写者分开，对库只读。

- **读者条件：**
  - `store_only`（主测量）：没有论文；A3 的 ReadEvidence 只读产物文档，`FetchArtifact` 可用；
  - `with_papers`（E2 用）：读论文不阻止，事后审计；
  - 闭卷下限与神谕上限（§4.3）。
- **落在多写者交汇处**（[Intent 分解](./intents_decompose.md) §7.1.2）：被两个以上写者在不同意图下写过的对象；经历过修订、撤回或分歧的记录；输入已被修订的产物；被几个写者编辑过的共同产物，尤其是同一格有多个值、或他人的行被改过的地方；所需内容由另一意图的写者写下的问题（C5）。
- **来源：** 正式探针一部分从 PwC 抽取（外部、事先存在的银标准，按论文分层），一部分按意图新写。写探针的人不改算子。先导探针（`experiments/t1/config/probes-ltsf.yml`，A1–G2）只用于设计。
- **有效期：** 一个探针在其金标准最早涉及的论文写入后的检查点起有效；版本事件探针的金标准按检查点分版本。
- **判分：** 读者回答末尾给出 `claims` 清单，按（论文, 方法, 数据集, 预测长度, 指标, 数值）成对计召回，逐条对照原文计精确率（沿用 pilot-2 的判分，`experiments/t1/src/t1/grade.py`）。
- **冻结时标注：** 意图（I1–I6）；所在层；交汇类型（以上之一，或无交汇）；是否依赖注入事件。无交汇的探针作为对照：A3 在这类探针上不应有优势，有优势反而说明收益来自别处。

## 3. 对照组与消融

### 3.1 对照组

| 组 | 配置 | 用于 | 回答的问题 |
| --- | --- | --- | --- |
| **A0 文件加 git** | 共享一个 git 仓库，Agent 用 markdown 自由组织，允许自建索引、目录约定和 AGENTS.md；拿到种子文件，没有 schema，也没有维护提示 | E1、E2 | 最强的反驳：通用 Agent 自己能否维持共享积累的质量 |
| **A1 RAG** | **[已商定：只用于 E2]** 论文原文分块进入向量索引，读者经检索访问；给它与 A3 写入阶段同等的预计算预算（可用于生成摘要等） | E2 | 不整理、只检索，能否同样支撑工作负载 |
| **A2 同一 schema 的裸图库** | **[提议]** 同一 schema（含 Artifact 节点）放在裸 Neo4j 上；产物文档就是文件，写者用 Cypher 加文件编辑；没有身份查重、校验、版本、编辑提示与过时附注；拿到同样的种子 | E1、E2 | 通用后端加合适的查询是否就够了；A2 与 A3 之差只来自机制 |
| **A3 完整系统** | PaperWeave 默认配置 | 全部 | — |
| **A4 agent memory** | **[提议]** 同一个 pi 经 MCP 接入 Graphiti；内部抽取与更新用与 pi 相同的模型，内部调用计入成本；只做文档推荐的配置，不为本负载调参；按它自己的语义裁决冲突 | E3、E1 | 单主体记忆“由内部整合者裁决”的语义，在共享场景下是否退化；作为 memory，A3 是否吃亏 |

**[已商定]** 必须给 A0 最强配置。A0 与 A3 共用文件层，二者之差正好是图层与产物层上的机制。A2 与 A3 共用 schema，二者之差只来自机制；与 A0、A1、A4 的比较混有 schema 的作用，需如实标出。

**[已商定]** 最小组别：E1 为 A0、A2、A3、A4；E2 另加 A1。

### 3.2 消融

**[已商定]** 每项消融拿掉一个机制，在 A3 上进行，只跑 4 个伪用户的条件：

| 消融 | 去掉什么 | 预期主要伤到的指标 |
| --- | --- | --- |
| **−身份** | Commit 不给出候选、不要求确认；每次新建都生成新节点 | M1 重复率、M4 碎片化 |
| **−共同编辑** | 产物退回旧版：每次调用新建、写入后不可修改，没有身份键 | M4 碎片化、M6 知识流失、M11 采用率 |
| **−写入时提示** | Commit 不返回相关的共同产物 | M11 采用率，进而 M4 |

预期结果呈对角线：每项消融主要伤到它对应的指标。−契约、−谱系推迟到 revision。

另有读侧的受控对比放在 E2（§5.2）。

## 4. E1 完整性：多写者积累时间线

### 4.1 语料：先导，然后正式运行

**[已商定，见 [T1 先导语料](../../decisions/2026-10-10-t1-pilot-corpus.md)]** 先导选了三个领域：时序预测（主榜单 ETTh1）、节点分类（Chameleon），这两个重叠高；关系抽取（DocRED），重叠低，作对照。每个领域按固定规则抽 10 篇：最早 2 篇作种子论文，其余 8 篇交给写者。

pilot-1、pilot-2 在时序预测上跑了 A0 与 A3（[pilot-2 冻结记录](../../decisions/2026-10-11-t1-pilot-2-freeze.md)），数据降为探索性。下一次先导（pilot-3）在新算子实现之后进行，用途：

- 跑通“种子 → 伪用户 → 探针 → 审计”的全流程；
- 实测写入重叠与采用率；
- 估计方差与单篇成本，用来定正式规模。

**正式运行：** 领域与规模在 pilot-3 之后再定；语料按发表时间排序，写者按时间顺序接触论文；跨领域的对比只作辅助证据。

### 4.2 因子与主估计量

**[已商定]** pi 的每次会话都是全新的上下文，所以单个伪用户的许多会话本身已是不协调的写者。$K=1$ 与 $K=4$ 的真正差别，是意图多样性、同一篇论文被读两次，以及“自己的”与“他人的”之分。因此把 $K$ 拆成两个可以单独干预的因子：

| 因子 | 取值 | 操纵的是什么 |
| --- | --- | --- |
| 写者构成 | 1 个伪用户（单一背景 I3）对 4 个伪用户（I3、I2、I5、I1） | 意图多样性与身份 |
| 同篇重叠 | 0% 对 25% 的论文分给两个伪用户 | 同一对象的分歧（ShareMem 式的重叠干预） |

最小方案只做写者构成，同篇重叠固定为 25%；预算允许再补重叠这一维。两种条件的论文、顺序、种子与分配种子完全相同。

**主估计量：** 同一论文序列、同一检查点上，

$$
\Delta_{\text{arm}} = Y_{\text{arm}}(\text{4 个伪用户}) - Y_{\text{arm}}(\text{1 个伪用户})
$$

其中 $Y$ 为探针正确率或知识流失率 M6（取负）。E1 成立，指 $\Delta_{\text{A3}}$ 显著小于 $\Delta_{\text{A0}}$，即 A3 的多写者代价更小。随写入量变化的曲线作为辅助。

### 4.3 度量

在每个检查点上测量，按组别与写者构成分组。

**下游正确率（主指标之一）：** `store_only` 读者在 §2.4 探针上的正确率。

- 有据层探针以原文锚点为金标准；解释层探针见 M10。
- **参照线：** 闭卷下限（不给库也不给论文，闭卷能答对的探针剔除或单独报告）；神谕上限（直接给出金标准中的记录与锚点，仍答错则问题在读者）。
- **逐题归因：** 每个答错的探针，依据调用轨迹并回到库中检查，归入：1. 库里没有，或存错了（写侧）；2. 库里有，但没找到（读侧，C5）；3. 找到了，但读错或用错（读者）；4. 绕开库读原文才答对（不计作库的收益）。各组的差异应主要落在第 1、2 类；如果 A3 的优势主要来自第 3 类减少，结论要改写为“读侧接口让读者读得更顺”。

**库健康度：** 记 $R_t$ 为检查点 $t$ 时库中的结果行，$C^{ok}_t$ 为其中与原文一致的格子。

| # | 指标 | 定义 | 金标准 | 可测的组 |
| --- | --- | --- | --- | --- |
| M1 | 重复率（按对象类型） | 冗余节点占比：$1 - \lvert\text{现实对象}\rvert / \lvert\text{节点}\rvert$ | 抽样标注；外部标识给部分真值 | A2、A3、消融；A0 抽样 |
| M2 | 误合并率 | 一个节点涵盖多个现实对象的比例；与 M1 一起报告 | 同上 | 同上 |
| M3 | 悬空引用率 | 解析不了的引用 ÷ 全部引用 | 确定性 | 全部（A0 查文件链接） |
| M4 | 产物碎片化 | 每个身份键上的产物份数；每个真实方法在表中的行组数 | 确定性加实体标注 | A2、A3、A0（种子格式部分） |
| M5 | 转录忠实度 | $\lvert\{r \in R_t : \text{值与原文一致}\}\rvert / \lvert R_t\rvert$，按错误类型拆开 | 原文锚点，PwC 为辅 | 全部（A0 按可解析覆盖报告） |
| **M6** | **知识流失率（主指标之一）** | $\mathrm{Loss}(t) = \lvert C^{ok}_t \setminus C^{ok}_{t+1}\rvert / \lvert C^{ok}_t\rvert$ | 由 M5 推出 | 全部 |
| M7 | 无理由改动 | 改动他人内容且没有理由的次数；读者读到被改内容时是否得知 | 变更日志或 git | 全部 |
| M8 | 冲突检出率 | 同一论文同一格出现不同值时，被发现并回到锚点修正的比例 | 注入事件加自然发生 | 全部（经探针） |
| M9 | 过时识别 | 事件之后，依赖它的产物被标为过时的查准率与查全率 | 依赖关系，由事件构造 | 全部（经探针） |
| M10 | 分歧保留率与可见率 | 不同判断是否都在且各带来源；探针触及时读者回答是否提到分歧 | 构造 | 全部 |
| M11 | 采用率 | 新结果落进共同产物而不是私人笔记的比例；写者找到已有表的比例 | 调用轨迹 | 全部 |

- **[已商定]** M6 与探针正确率同为主指标，并且必须和 E2 的覆盖一起读：空库没有 $C^{ok}$，也就谈不上流失。
- M1 按对象类型拆开（Paper、Dataset、Task、Method），检验“外部锚点越弱，退化越多”：预期 Paper 接近 0，Method 最高。
- “改动他人内容”本身不算退化。退化的是两种情况：改了却没有理由；读者在不知情的情况下读到了被改过的内容。A0 也能改他人的笔记，git 也有历史，所以要比的是改动在读取时是否可见、理由是否留存。

**观测量（不作为主张）：** 使用次数与正确性是否相关（错误级联）；写入内容装不进类型的次数及去向；绕过率（§7.1）。

现有的统计脚本 `experiments/t1/src/t1/health.py` 覆盖 M3、M5、M7（旧口径）与 M1 的候选聚类，按新产物与新指标扩展。

### 4.4 审计 DAG

**[已商定：先作为评测工具，效果好再讨论是否转为贡献]** 共同产物的格式是软的，但被强制的部分（键、引用、出处）足以让审计确定性地完成。以 Leaderboard 为例：

```text
解析文档 → 解析 id → 规范化行键 → 出处核对 → 对照 PwC → 跨论文比对 → 剩余项裁决 → 错误分类
```

| 节点 | 产出 | 对应指标 |
| --- | --- | --- |
| 解析文档 | 解析失败（格式漂移） | 格式漂移率；M5 的可解析覆盖 |
| 解析 id | id 不在库中 | M3 |
| 规范化行键 | 同一方法裂成几组行；同一键上几份产物 | M4 |
| 出处核对 | 数字不在所引的行中 | M5 |
| 对照 PwC | 与银标准不一致的格子 | M5 |
| 跨论文比对 | 同一格多值：同论文是抄错，不同论文是并存 | M8 |
| 剩余项裁决 | 前面没定的格子交强模型对照锚点裁决 | M5 |
| 错误分类 | 抄错数字、张冠李戴、设置写错、引用旧版本、无依据 | M5 的拆分；逐题归因 |

跨产物的节点：CompareSettings 说某维度相同、而两行对应的列不同，记为判断与数据矛盾；Verify 引用的数值与 Leaderboard 当前的行不一致，记为过时的核查。

- **A0 的解析：** A0 的种子 Leaderboard 是同一格式的 Markdown 文件，写者照着写的部分同一个 DAG 能解析，解析失败率本身就是“格式漂移”的度量；写进私人笔记的部分，用现有的临时解析器加抽样标注，覆盖率如实报告。
- **循环论证的划分：** 出处格式、id 存在、数字在所引行中，A3 在写入时已经检查，这几项只用来比较 A3 与消融、A2、A0；对照 PwC、张冠李戴、设置写错、跨论文一致性与知识流失，系统不检查，这些才是 E1 的证据（§1.4）。
- DAG 是评测代码，不进入系统；它不调用 LLM，剩余项裁决单独计数。

### 4.5 统计

- **[提议]** 统计单位是独立的时间线。各组、两种写者构成用完全相同的论文序列与分配，配对比较。用混合效应模型：探针与时间线作为随机效应，组别 × 写者构成的交互项是要检验的固定效应。置信区间用按时间线聚类的 bootstrap。
- 每种配置先跑 2 种分配种子，第 3 种视 pilot-3 测出的方差而定。
- 审稿人可能会问：加了约束更好，这不是理所当然吗？真正有信息量的是两件事：文件加 git 在什么规模、什么重叠下开始输；输掉的部分具体来自哪种退化。因此拐点与消融归因比最终分数更重要。如果 A0 在可负担的规模内始终不输，这本身就是值得报告的结果，主张要相应收窄。

## 5. E2 充分性

### 5.1 按意图的充分性

在 E1 的检查点快照上，同一批探针分别由 `store_only` 与 `with_papers` 读者回答。按 I1–I6 分别报告：

$$
\rho_I = \frac{\mathrm{Acc}_{\text{store\_only}}(I)}{\mathrm{Acc}_{\text{with\_papers}}(I)}
$$

$\rho_I$ 接近 1 的意图，库能独立支撑；远低于 1 的，仍需回读论文。同时报告 $\rho_I$ 随积累的变化：积累的价值在于差距缩小。

- **A1 的位置：** A1 不整理、只检索论文分块，给同等的预计算预算。若 A1 在某个意图上与 A3 `store_only` 相当，说明这个意图不需要整理；这是对“由意图推导读取面”这一设计方法的检验。
- I3 依赖结构化结果能否合成表格，这是 Leaderboard 的用武之地；预期 I3 的 $\rho$ 最高，I2、I4 较低。

### 5.2 读侧受控对比

**[提议]** 在 A3 某个检查点的快照上，固定库的内容，只换读侧：

- **访问算子 vs Cypher：** 同一份知识、同一个 Agent、同样的预算，对比 PaperWeave 的访问算子与有充分 schema 说明的 Cypher（即 A2 与 A3 的读侧差异）；
- **分歧与过时随结果返回 vs 不返回：** 检验“读者不会主动查 provenance”这一条改变；
- **检索面消融：** 词面、向量、融合；关系硬过滤、关系扩展、完整视图装配。

这部分只回答使用阶段的问题，与 E1 的全流程对比分开报告。

## 6. E3 对等与成本

### 6.1 非劣效检验

**[提议]** 在 1 个伪用户的条件下，A3 对 A4 做非劣效检验：

$$
\mathrm{Acc}_{\text{A3}} - \mathrm{Acc}_{\text{A4}} > -\delta, \quad \delta = 5 \text{ 个百分点}
$$

$\delta$ 在冻结协议中预先声明。4 个伪用户条件下的 A4 结果归入 E1。不跑 LongMemEval、DMR 等对话记忆基准，它们不是本文的工作负载。

### 6.2 成本账本

成本分项记账，在每个检查点报告增量与累计值；失败的调用和对原文的直接读取都要计入：

- **构建：** 入库的 token 与时间，dry_run 来回轮数；
- **写回：** 产物检出、编辑、检入与校验的额外开销；
- **使用：** 每次下游任务的成本；
- **维护：** 修订、撤回、材料变更之后的复检开销；
- **A4 的内部调用：** 记忆系统内部 LLM 的调用。

盈亏平衡点：

$$
N^* = \frac{C_{\text{build}}}{c_{\text{base}} - c_{\text{ours}}}
$$

其中 $C_{\text{build}}$ 是构建与维护的总成本，$c_{\text{base}}$ 与 $c_{\text{ours}}$ 分别是对照组和 A3 每次使用的成本。

成本的三种表述：

1. **写回开销。** 知识积累是 Agent 正常工作的副产品，它本来就要读论文。报告的是比“只读不写”多花了多少，而不是整个库的构建费用。
2. **摊销。** 共享库由许多使用者分摊，$N^*$ 随使用者数增加而更容易达到。前提是对照组拿到同等的预计算预算。
3. **离线与在线用不同模型。** 构建阶段用便宜模型，使用阶段用强模型。

平台级成本只放在讨论部分，作为粗略估算。

## 7. 可用性与系统开销

### 7.1 Agent 是否用得顺手

这些指标必须和正确率一起报告：

- **交互效率：** 工具调用次数、无效调用率、dry_run 来回轮数、被拒写入后的恢复率；
- **显示偏好：** Agent 保留了文件与 shell 权限，只审计、不禁止它绕过 PaperWeave。它多常绕开、直接读原文，本身就是“好不好用”的证据。绕过所得的答案不计作复用。

### 7.2 系统开销与可扩展性

**[提议]** 测量对象是存储层本身，不经过 Agent：

| 测什么 | 自变量 | 对照 |
| --- | --- | --- |
| Commit 延迟，含 dry_run 查重 | 库中对象数、单批大小 | A2 直接写 Cypher |
| 产物检入延迟，含版本比对与编辑提示 | 文档行数、版本数 | 不比对的直接写入 |
| 访问算子延迟（Search、Traverse、ReadEvidence、FetchArtifact） | 库中对象数、遍历扇出 | A2 的等价 Cypher |
| `_stale` 读取时计算的开销 | 依赖链深度与扇出、产物形成之后的提交数 | 不返回过时提示 |
| AsOf / Diff 延迟 | 历史长度（提交数） | — |
| 存储增长 | 提交数；graph-vc 变更集与产物版本相对当前状态的体积 | 无版本的库 |

规模的来源分两部分：真实的语义实例来自 E1 时间线，负责正确性；扩展到更大规模时，用 OpenAlex 元数据批量导入身份锚点，再重放或复制 E1 的写入序列。生成的数据只用于压力测试，并单独标注。

## 8. 金标准

### 8.1 按层定义

**[已商定]**

- **有据层与结果行：** 对照原文锚点。对错指是否忠实于原文，不是科学真理。
- **解释层：** 不测真值，只测分歧是否被保留、读者是否看得到。
- **身份：** 实体对齐抽样标注；外部标识（arXiv ID、DOI、仓库 URL）给出部分真值。

**核查者：** 审计 DAG 的剩余项裁决与银标准裁决由强模型对照锚点完成，再用人工抽检校准一致性（如 Cohen's $\kappa$）。核查模型与 pi 的写入模型不同源（候选是 gpt6-astra）。人工抽检的比例事先固定。

### 8.2 PwC 银标准

**[已商定]**

- PwC 快照已经固定（`data/raw/t1-pilot-corpus/pwc/`），是外部、事先就存在的参照。先导语料中 10 篇有 7 篇有可用条目，探针按论文分层抽取。
- 它是银标准，不是金标准。与 PwC 不一致时，回到原文锚点裁决：我们对而 PwC 错；PwC 对而我们错；两者都说得通（例如一方用自报数字、一方用重跑数字）。这些不一致本身可以作为分歧与修订事件的真实取材。
- PwC 把设置编码在数据集名里（如 `ETTh1 (336) Multivariate`），对照时拆成数据集、预测长度与变量设置。
- 写者不能看到 PwC。是否断网待定；在此之前，审计这类访问。

### 8.3 公开数据的用途

| 来源 | 可用的部分 | 不足与使用方式 |
| --- | --- | --- |
| Papers with Code 归档 | 任务、数据集、结果榜单 | 银标准（§8.2）；覆盖面小，录入不完整 |
| TDMS（Hou et al. 2019）、AxCell、SciREX | 任务、数据集、指标、结果的标注 | 实体对齐与结果行的参照；领域覆盖与可获取性待核查 |
| LEGOBench（`2024-LEGOBench`）、SciLead（`2024-SciLead`） | 排行榜生成任务；人工整理的 TDMR 排行榜 | Leaderboard 转录的参照；规模较小 |
| [AstaBench：ArxivDIGESTables-Clean](https://github.com/allenai/asta-bench/blob/main/README.md#available-tasks) | 跨论文结构化比较表 | I4 探针的形式；不沿用官方分数 |

## 9. “不变式 × 合并”分析框架

标题 *Collaborating without Coordinating* 会让审稿人期待 I-confluence、CALM 那样的分析：哪些不变式不需要协调就能维持。按“两个各自合法的写入合在一起后是否仍然合法”给库的不变式分类。本轮只走直写路径，“合并”就是一次提交或一次产物检入与当前库状态的合并。

| 不变式 | 合在一起时 | 维护方式 | E1 中的检查 |
| --- | --- | --- | --- |
| 来源与谱系完整 | 并集仍合法 | 无需介入 | M3 |
| 解释层判断并存 | 并集仍合法，分歧本身就是数据 | 无需介入 | M10 |
| 实体身份唯一、引用完整 | 可能违反，例如两边各建了一个 PatchTST | 提交时查重，由写者确认 | M1、M2 |
| 一个键一份共同产物 | 可能违反，例如两边各建一张 ETTh1 表 | 身份键撞键时退回已有那份；`base` 过期时拒绝，写者重新取出后合并 | M4 |
| 有据层单值 | 可能违反，例如两边对同一结果读法不同 | 回到原文锚点修订，保留历史 | M5、M8 |
| 改动他人内容有理由、可见 | 可能违反 | 检入时要求理由；读取时附编辑提示 | M7 |
| 派生产物新鲜 | 输入变化后，产物可能过时 | 依赖追踪：只标记，不重算 | M9 |

T1 的度量按这几行分组报告（§4.6 表 3）。各行的结论按定义看大体成立，但还没有形式化；做到一个命题加逐条论证即可。

**[已商定] Fork / Merge 不在本轮范围内。** 它是另一条思路，贡献维度与主模块不一致。等主模块（身份、共同产物、版本与过时）的贡献确定能成立之后，再讨论是否纳入。设计见 [项目视图](./project_views.md)。

### 10.1 评测代码与被测系统分离

**[已商定 2026-10-14]** 用被测系统自己的代码去测它，系统的错误会同样出现在测量里而不被发现，基线组的内容也会随系统代码变化。因此评测代码与系统分开，规则如下。

- **不导入。** `experiments/t1/` 不导入 `e09`、`graph-doc`、`graph-vc`：graph-vc 承载的版本机制是被评测的对象之一（C4），同样算被测系统。t1 的依赖只有 Neo4j 驱动、pyyaml 与标准库；用一个扫描 import 的测试守住，违反即失败。
- **只经外部接口交互。** 评测与系统之间只有三种接口：
  - 子进程入口：用系统的命令行种库，用系统的 MCP 服务给写者提供工具；
  - 库的原始状态：按 [Graph Model V2](./graph_model_v2.md) 写明的标签与属性，用 Cypher 直接读 Neo4j；
  - 磁盘上的文件：论文材料、产物文档、A0 的 git 仓库。
- **检查点即冻结的快照。** 运行到每个检查点时，框架立即把库导出为中立的快照（节点、边、提交记录与产物文档的副本），之后的测量只读快照，可以离线重算，不再事后回放版本历史。A0 在每个检查点打 git 标签，导出成同一形状，两组接受同一套测量。A0 的检查点 0 由 A3 检查点 0 的快照渲染，两组起点内容相同的前提照样成立。
- **测量用自己的解析器。** 产物文档（Leaderboard 的表格、来源引用的写法等）按[算子契约](./operators.md)写明的格式独立解析，不复用系统的类型契约。两边解析结果不一致本身就是发现。这也是“不拿自己的校验考别人”（§1.4）在代码上的落实。
- **标准是数据。** 金标准、rubric 与指标定义以数据文件冻结在 t1 中，正式运行前与用户确认；测量代码只负责解释它们。
- **代码分两层。**
  - `harness`：调度、沙箱、转发、种库、导出快照、渲染 A0。可以依赖 Neo4j 驱动。
  - `measure`：库健康度、审计 DAG、探针评分及其解析器。只依赖标准库与 pyyaml，只读快照，不连库。

现有的 t1 代码不满足这些规则：路径常量、A0 种子的重放与渲染、库健康度的产物解析与状态读取都还导入了系统代码。随评测框架的改写（arXiv v1 待办的 C 部分）一并改正，不单独返工。

## 12. 风险与可能的负结果

- **写入重叠不足。** 写者很少撞上同一对象，E1 测不出差别。应对：先改论文分配，提高同一领域内的交集；仍然不足，就如实报告并重新考虑领域。不能为了制造重叠而人为指定写者写什么。
- **采用率低。** 写者不去找、也不维护共同产物，A3 退化为“各写各的”。这是一个真实的发现，不改任务提示去迎合它；−写入时提示的消融说明提示的作用。
- **A0 不输。** 在可负担的规模内，A0 的多写者代价与 A3 相当。这时报告文件加 git 足够的区间，把主张收窄，不换成对我们有利的负载。
- **收益来自读侧，而非积累的质量。** 逐题归因中 A3 的优势主要落在第 3 类时，结论相应改写。
- **循环论证。** 拿 A3 已经检查的项去比 A0。按 §1.4、§4.4 的划分避免。
- **A4 配置被质疑。** 只用文档推荐的配置；说明这正是要检验的前提差异，即单主体与共享。
- **约束的代价超过收益。** 校验与拒绝导致写回成本过高，Agent 频繁绕开 PaperWeave。显示偏好与恢复率会直接暴露这一点。
- **退化只来自某一项机制。** 如果消融显示只有身份查重有效，主张相应收缩。
- **按评测定做算子的质疑。** 算子与探针都从意图推出；先冻结算子与种子，再写正式探针；论文中写明产物层是按这个工作负载设计的。
- **泄漏。** 写者查到 PwC 归档；模型记得榜单数字；种子与金标准重合。逐项审计。
- **judge 偏差。** judge 与写者、读者的骨干模型不同源；人工抽检比例事先固定；报告方差与显著性。
