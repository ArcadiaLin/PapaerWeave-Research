# 与 Graphiti（A4）对比时，哪些指标还成立

> **状态：** 2026-10-16 讨论稿，未与用户商定，回头再定。起因：读完 Graphiti 的论文与实现（`references/repos/graphiti`、`references/repos/zep`）之后，回头检查 [评测草案](../designs/v2/evaluation_draft.md) 中与 A4 对比的部分。未改评测草案。
>
> 按评测草案 §11.1，arXiv v1 不做 E3，本稿针对投会议的版本。

## 1. 结论

- **框架仍然成立**：E1 的多写者代价 $\Delta_{\text{arm}}$ 加探针正确率、E3 的非劣效检验、成本账本，在 A4 上都能测。前提是探针与判分以金标准格子（论文、方法、数据集、预测长度、指标、数值）为单位，与数据模型无关。
- **M1–M11 约一半不能直接搬到 A4 上**：它们按 A3 自己的对象定义（结果行 $R_t$、产物、身份键、锚点、写入理由）。Graphiti 没有这些对象，搬过去会测不了、天然为零，或者变成"拿自己的校验考别人"（评测草案 §1.4）。
- **A4 有三处配置未定**，会直接影响结果是否可信（§3）。

## 2. 逐项检查

| 指标 | 在 Graphiti 上 | 建议 |
| --- | --- | --- |
| 探针正确率 | 能测：读者经 `search_nodes`、`search_memory_facts` 答题 | 保留；先定 `store_only` 能否读 episode（§3.2） |
| M1 重复、M2 误合并 | 能测，需要标注；Graphiti 抽出的实体有许多不属于四类对象（如 "Table 3"、"MSE"），分母只算能对应到真实对象的节点 | 加入 A4。正好对比"写者确认"与"内部 LLM 判断"两种实体解析 |
| M3 悬空引用 | 天然约为 0：A4 的写者不写引用，边由系统生成 | A4 记为不适用 |
| M4 产物碎片化 | 没有产物，也没有身份键 | 不适用；或改为按格子：同一金标准格子落在几条事实中（需标注） |
| M5 转录忠实度 | 数值在 LLM 改写的 `fact` 句子与摘要里，审计 DAG 无法确定性地解析 | 用 LLM 投影或抽样标注，单独注明口径 |
| M6 知识流失 | 按 $R_t$ 无法计算。Graphiti 另有自己的流失方式：摘要合并（不超过 1000 字）丢失内容；不同论文的数值被内部 LLM 判为矛盾，较早的一条被置 `invalid_at` | 跨组改用保持探针（§4）；按 $R_t$ 的定义留作 A0、A2、A3 的诊断 |
| M7 无理由改动 | Graphiti 的改动都在内部发生（失效、摘要重写），本就不记理由；"必须给理由"是 A3 在写入时强制的 | 在 A4 上只作能力描述，不作证据 |
| M8 冲突检出 | Graphiti 原生检测矛盾，但按时间裁决（后写的胜出），没有原文锚点可以回查 | 改为：最终留下的值是否与原文一致 |
| M9 过时 | 没有派生产物，也就没有过时的概念 | 记为"不原生支持"；探针照常提问 |
| M10 分歧保留与可见 | 能测，而且最能体现差异：两个写者的不同判断可能被判为矛盾，其中一条失效 | 保留，作为"裁决位置不同"的主要证据 |
| M11 采用率 | 没有共同产物 | 改为：写入之前是否先检索过（从调用轨迹判断） |

评测草案 §4.3 中，M1、M4 的"可测的组"没有列出 A4；M5、M6 写的是"全部"，但没有说明 A4 怎样计算。

## 3. A4 的三处配置

### 3.1 实体类型

Graphiti MCP 的默认实体类型（Preference、Requirement、Procedure 等，见 `mcp_server/config/config.yaml`）面向个人助理。直接用于论文知识，等于故意削弱对照组。Graphiti 文档推荐为领域定义自定义类型（Pydantic 模型）。

**建议：** 给 A4 同一套领域词表（Paper、Method、Dataset、Experiment 等，以及关系类型）。这与"领域词表是给定参数"的定位一致，M1 也可以直接按类型拆开。

### 3.2 `store_only` 下的 episode

写者可能把论文段落原样经 `add_memory` 写入；读者再用 `get_episodes` 读到的就是原文，`store_only` 就不成立了。

**建议：** A3 在 `store_only` 下不读论文行；对等地，A4 在 `store_only` 下只用事实与节点，不读 episode 内容。允许读 episode 的版本另作敏感性分析。

### 3.3 异步写入与危险工具

- `add_memory` 返回时内容还没处理。harness 必须在下一个写者开始前等队列清空，并单独记录抽取失败：写了但没有进库，本身就是一种流失。
- 默认配置开放 `clear_graph`、`delete_episode`。共享场景中一次调用就能清空整个库。需要事先声明是保留并记录，还是隐藏。
- Graphiti 不记录写者身份，"他人的内容"只能依据我们代理层的日志判断。

## 4. 建议的调整

- **指标分两层：**
  - 跨组比较只用与库结构无关的指标：探针正确率、保持探针（M6 的跨组版本）、M10。
  - 结构指标（M1–M5、M7、M9、M11 的原定义）只在 A0、A2、A3 及消融之间比较；在 A4 上逐项标为原生支持、经组合支持或不支持。
  - 评测草案 §1.4 已有"跨组以探针与知识流失为准"，这里是把它落实到每一项指标。
- **保持探针：** 每个检查点重复问同一批事实性探针；在 $t$ 能答对、在 $t+1$ 答不对，记为一次流失。这对任何组都可测，不依赖解析库的结构；能捕捉 Graphiti 的误失效、摘要丢失与抽取失败，也能捕捉 A0 笔记被覆盖。
- **系统开销加入 A4：** 每个 episode 的内部 LLM 调用数、入库吞吐、检索延迟。目前 §7.2 只以 A2 作对照；写入时中间件不调用 LLM 是一个明显的优势。
