## 1 总体判断

- **方向成立，证据还差关键几块。** 问题（互不协调写者的共享积累）、模型（按对象类别规定一致方式）与评测框架都已成形；f3 四组写者与 A3、P 读者已跑完，尚未判分。
- **最可能的结果形态**（判分前的倾向）：H2（多写者完整性）的差别更可能出现在版本与过时、写者成本上，而不在重复率上（lessons §8.2：k20 上两组重复都是 0、锚点形式有效都是 100%）；H1 的成本一侧是"代价转移"，不是全面节省（§3）。
- **最大的风险在结果本身，不在跑了几次。** A3 与 A0 差别大且能逐题归因到机制，一条时间线也站得住；差别接近 $\delta$ 时，只能如实报告"没有区分出来"并收窄主张（lessons §9.5）。

## 3 读者成本：怎样读（2026-10-24）

### 3.1 侦察结果

A3 读者记录 §4.3 中，每题 A3/P 全部 token 之比的中位数从 k10 的 1.27 降到 k20 的 0.93、k30 的 0.83，容易读成"进入 k30 后规模效益显现"。但三个检查点的题号是嵌套的（k10 的 53 题 ⊂ k20 的 69 题 ⊂ k30 的 200 题），固定题集后再看，这个趋势不成立。

一次性侦察（读回答记录中的 `usage` 与 `seconds`，未入库），每题 A3/P 之比的几何均值，方括号为对题 bootstrap 的 95% 区间。加权成本是示意的价格口径：未缓存输入 $\times 1$、缓存读 $\times 0.1$、输出 $\times 4$。

| 题集 | 检查点 | 全部 token | 加权成本 | 模型调用 |
| --- | --- | --- | --- | --- |
| 固定的 53 题 | k10 | 1.37 [1.03, 1.86] | 1.42 [1.17, 1.74] | 0.72 [0.63, 0.82] |
| | k20 | 1.17 [0.88, 1.55] | 1.28 [1.04, 1.58] | 0.62 [0.54, 0.72] |
| | k30 | 1.28 [0.97, 1.70] | 1.33 [1.09, 1.63] | 0.67 [0.58, 0.77] |
| k20 新增 16 题 | k20 | 0.56 [0.39, 0.81] | 0.74 [0.59, 0.93] | 0.49 |
| | k30 | 0.64 [0.47, 0.87] | 0.82 [0.65, 1.00] | 0.51 |
| k30 新增 131 题 | k30 | 0.76 [0.65, 0.89] | 0.92 [0.81, 1.05] | 0.63 |

固定 53 题按题型（加权成本，k10 / k20 / k30）：跨论文题 T3 0.70 / 0.32 / 0.64、T4 0.74 / 0.98 / 0.65、T5 0.69 / 0.74 / 0.69、T7 0.51 / 0.56 / 0.37（各 2–3 题）；单篇题 T2 约 2.0、T9 约 1.7、T10 1.4–1.8、T11 2.5–3.1、T14 2.1–2.8，三个检查点都如此。

### 3.2 结论

1. **同一批题，A3/P 之比不随规模下降。** 中位数的下降来自题目构成：严格有效规则要求题目涉及的论文全部入库，跨论文题因此集中在 k30（200 题中约三分之二是 T3、T4、T5、T7、T8）。这是有效规则的副产品，不能作为规模效应报告。
2. **最稳的信号是模型调用少 30–50%**，三个检查点、同一批题一致：库把读者的探索换成了查找。
3. **省下的轮次被更重的单轮抵掉**：输出 token 多、单题用时长；按价格加权，k30 新增题为 0.92，区间跨过 1。只看"全部 token"会高估节省，因为它把缓存读按全价计。其中一部分来自实现（20% 的证据引用因 16 KiB 回复上限要再请求；先经库定位再请求原文块），不全是库固有的代价。
4. **收益由题型决定**：跨论文汇总题在 k10 就已是 0.4–0.7；单篇查找题始终是 1.5–3 倍。
5. **整体上，H1 的"成本不高于 P"取决于题集构成。** 按加权成本、含辅助题的各检查点合计，A3/P 为 k10 1.20、k20 0.89、k30 0.86。
6. **摊还**：按同一价格口径，建库到 k30 约 37.9M 加权单位；k30 一轮读者（206 题）A3 比 P 少约 13.1M，约 2.9 轮收回。对价格表敏感，未计正确率，只作量级参考；判分后按每答对一题的成本重算。建库成本可给上下界：全算（上界）；只算相对 A0 多出的写入成本（下界），因为写者的任务本身有产出。

### 3.3 这组对照的有效性与范围

- **设计没错，错在读法**：A3 与 P 同题、同模型、同读者设置、逐题配对，回答的正是 R13"原文在手不就行了"。错误是把题集不同的检查点的聚合数连成规模曲线。
- **比 agent memory 文献的惯例更严格。** Mem0、Graphiti 的成本优势来自 full-context 基线（整段历史塞进上下文：Mem0 26k → 1.8k tokens，Graphiti 115k → 1.6k tokens；见各自精读笔记）。P 是会自己找的 agent，按需读取，本身就有选择性，所以省不出数量级。审稿人难以说基线是稻草人。
- **P 是理想情形，结论偏保守**（评测 V3 §3 已写明）：论文已找好、放好；真实读者还要先发现论文、分辨版本，库替读者做了这一步。可以这样写，但不给数字，我们没测。
- **它只测了库的一种用途**：把库当作原文的索引。P 能答的题答案都在原文里；他人的判断与制品、分歧、过时提示、多写者下的完整性，这组对照测不到，由 H2、H3 与版本更新的审计承担。
- **10–30 篇只有 3 倍跨度**，这个范围内 P 在全文中 grep 仍然便宜（固定 53 题，P 的总 token 从 k10 到 k30 只涨约 40%），看不出语料规模效应。

### 3.4 应当怎样讲

- **讲题型与工作负载，不讲"规模效益在 k30 显现"。** 推荐说法：库对跨论文汇总题有成本优势，对单篇查找有间接访问的开销；净收益取决于工作负载中汇总题的比例；在 30 篇以内没有观察到随规模扩大的趋势。可把汇总题比例作为参数画净成本曲线。
- **规模的作用要说清机制**：篇数越多，值得问的跨论文问题越多、每题涉及的论文越多，汇总题在工作负载中的比重上升，库的净收益随之上升。是工作负载变了，不是同一道题在大库上变便宜。
- **数据库的类比**：库对汇总查询像物化视图（写入时付费、读取时摊还），对点查是一层额外的间接访问，基表小到可以扫描时反而更贵。这正是访问路径选择的经典取舍，数据库审稿人熟悉。类比要求同时给出摊还账（§3.2 第 6 条）。
- **与主线接上**：跨论文结构不是一个写者建成的（三张排行榜由不同写者轮流维护 14 次），所以跨论文收益本身就是共享积累的结果。它补充 E1，不替代 E1。
- **用"跨论文汇总负载"，不用"大型数据库"**：30 篇称不上大型。
- **单篇题如实报告**：成本是 P 的 1.5–3 倍，判分后看是否换来同等的正确率。

### 3.5 待做（侦察，不改任何东西）

- **按题目跨越的论文数分析成本**〔待定〕：把"规模"从语料篇数换成查询范围，在 k30 现有数据上看 P 的成本是否随跨度变陡、A3 是否更平。口径要用证据锚点所在的论文数，不直接用 `requires`（覆盖全语料的汇总题会列出全部论文，口径偏宽，lessons §7.3）。
- **真正只变规模的测试**〔待定，代价大〕：同一道跨论文题在 k10、k20、k30 各给一份金标准。要新出题、先冻结。

## 5 改进方向：加哪一种量

原则：**沿主张依赖的那个维度加，不全面加。** 全面加最贵，说服力不一定更强。数据库会议对这类工作看的是严谨（主张都有度量、有重复与区间、失分能归因、机制的可扩展性单独测过、规模局限写明），不只是规模。30 篇配齐这些，比 100 篇只跑一次更站得住。

| 加什么 | 支撑的主张 | 成本 |
| --- | --- | --- |
| 读者重复作答 | 题层面的结论稳不稳 | 每组每轮约 10–11 小时墙钟 |
| 写者时间线重复（估 $\sigma_b$） | 结论能否推广到"再建一次库" | 每组每轮约 10–16 小时，另加读者 |
| 单写者时间线 | E1："增加写者"的代价 | 一条时间线 |
| 机制的可扩展性 | R4 | 不用 LLM，合成负载即可 |
| 扩大语料（60–100 篇） | 规模主张 | 最贵，瓶颈在出题与金标准 |
| 同一语料上加题 | 题型分层更细 | 中等；帮不了规模主张 |

建议顺序〔待定〕：

1. **不跑新实验的分析**：判分；§3.5 的跨度分析；逐题归因；版本更新的过时审计（lessons §8.3 第 1 项）。这些决定后面值不值得加量。
2. **读者在 k30 上重复 2 次**，覆盖进入主结果的所有组。
3. **机制的可扩展性测量**：把图放大 10–100 倍，测提交延迟、`_stale` 开销、存储增长；不占推理服务。
4. **单写者时间线。**
5. **每组再建 2 次库**，主要用来估 $\sigma_b$（每组 3 次时自由度仍小，区间很宽；所需次数见 lessons §9.4）。约 2 天服务器时间。
6. **扩语料**：有条件地做，判分后跨论文题的优势确实存在、论文确实要主张规模时才做；题与规则先冻结，不为找占优的区间挑工作负载。

分阶段：arXiv 预印本用现有规模，做完 1–3，局限一节写明一条时间线、30 篇；投会议的版本按判分结果决定 4–6 做到哪一步。

## 6 叙述要点

**措辞**

- 用"跨论文汇总负载""代价转移"，不用"规模效益在 k30 显现""大型数据库"（§3.4）。
- 不写 "provable"；写清库确定性保证什么、不保证什么（R5）。
- 用 integrity，不用 data quality / data cleaning（AGENTS.md）。
- 不用 "shared memory"；"memory" 不引入技能提炼、整合、遗忘等工作负载不需要的功能（AGENTS.md）。
- 相关系统的共同假设放宽为：或由内部 LLM 覆盖改写（ShareMem），或只追加、由检索相似度决定读者看到哪一条（Collaborative Memory）；两者都不对照来源核对，也不让读者看到条目之间的分歧（lessons §2.1）。
- provenance 的用途：for accountability，不是 for access（lessons §2.3）。

**证据的边界**

- 每条主张配一个度量与证伪条件（评测 V3 §3）。
- A3 写入时就强制的检查只用于 A3 对 A2，不作为胜过 A0、A4 的证据；k20 上锚点形式有效两组都是 100%，不是 A3 的优势（lessons §8.2）。
- 结论以"这一次建出来的库"为条件；库层指标只做描述，不报显著性（lessons §9.2、§9.3）。
- A0 第 38 号会话超时单独决定了 Bi-Mamba+ 相关约 30 题的差别，要单列解释，不算作机制的胜利（lessons §7.3）。
- P 的理想情形让 H1 偏保守，可以说，不给数字（§3.3）。
- 成本口径要全：建库、写回、使用、维护都计入（V2 评测 §6.2）；不只看全部 token，缓存读另计或按价格加权。
- 正文数字与图表终稿前逐个核对；引用审稿意见前确认是官方决定页（lessons §6）。
