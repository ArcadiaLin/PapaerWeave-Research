# F4-0：从 f3 读者轨迹拆解读取成本（2026-10-25）

状态：抽取、核对与作图已完成（2026-10-25）；不新跑读者，不占推理服务。代码（`pweval.measure.read_cost`、测试、notebook）尚未提交。
设计依据：`docs/experiments/f4/2026-10-25-f4-design.md` 第 3 节（下称 f4 设计）。
数据来源：f3 的 A3、A0 读者（`docs/experiments/f3/read/2026-10-24-f3-A3-readers.md`、`2026-10-24-f3-A0-readers.md`，下称 A3、A0 读者记录）与 f2 原文组 P（`docs/experiments/f2/2026-10-21-ref1-P-originals.md`，下称 P 记录）。

## 1 目的

f3 中 A0 读者比 A3 省（A0 读者记录第 5 节），但模型调用与工具调用反而更多。f4 设计第 3 节列出四种可能的来源：E-a 粒度（MCP 要多轮往返）、E-b 输出冗长（search、get、traverse 的返回过长）、E-c 固定开销（工具描述每轮占上下文）、E-d 原生工具（只有真正的文件能拿到）。F4-0 用现有轨迹把成本拆开，看哪些成立；结论用于解释 A3F 的结果，不决定是否实现什么。

## 2 数据与口径

**范围**：A3、A0、P 三组，k10、k20、k30 的主题集（53、69、200 题），不含辅助题；共 966 个会话。三组的题号逐检查点相同，所有比较按题配对。

**题是嵌套的**：k10 的 53 题都在 k20 的 69 题中，69 题都在 k30 的 200 题中。所以结果按两种口径报告：

- **同一批 53 题**：题不变，只有库变大，看规模的效应；
- **各检查点的全部题**：题的构成也在变。k30 新加的 147 题中，跨论文题 71 道、单篇查找题 4 道、其他 72 道。

**来源**：只读各组的回答记录（`answers/<组>/k<K>.jsonl`）与其中登记的事件流。事件流中有每次模型调用的 usage（input 不含命中缓存的部分，cacheRead 另计）、每次工具调用的参数与返回文本、压缩事件。

**指标**：

- 每题用时、未缓存输入、缓存读、模型调用：与读者记录同源，这里按每题平均报告，便于跨检查点比较。读者记录报的是含辅助题的合计。
- **提示 token**：每次调用的 input 加 cacheRead，按题求和。
- **驻留成本**：一段内容进入上下文后，之后每次调用都会再读一遍，直到压缩。每题的提示 token 拆为五项：
  - 固定前缀：第一次调用的提示（系统提示、工具定义、题面）乘以调用次数；
  - 助手输出：每次的 output 乘以它之后留在上下文中的调用次数；
  - 查找类工具的返回：A3 为 search、get、traverse、log、show、checkout、as_of 以及少量 bash、read；A0、P 为 bash 与 pi 的 read；
  - `read_evidence` 的返回；
  - 残差。
- **工具返回的 token 数**：逐步分摊。相邻两次调用之间提示 token 的增量，减去上一次的输出，就是这一步新加入的工具返回的 token 数，按字符数分给这一步的各次返回；只有一次返回的步骤即为精确值。算不出增量的调用（会话末尾、跨压缩、增量不为正），才按字符数除以该组校准的比例估计：A3 87 次、A0 37 次、P 26 次，共 22,001 次工具调用。
  - 不用统一的比例：表格中的数字切出的 token 多，统一的比例会在工具之间错配。
  - 这一拆法的前提是思考内容留在上下文中。有两条依据：一是读者会话只有一条用户消息，按模型的 chat template，此后的思考都会保留；二是若思考不保留，大量步骤的"增量减输出"会是负数，实际在数千步中只有几十步。
  - 未压缩的会话残差恒为 0（由这一拆法决定）；残差只出现在压缩过的会话中，是压缩摘要与保留下来的末段。
- **查找的形状**：每题查找调用次数、单次查找返回的字符数（中位数）、第一次成功的 `read_evidence` 之前的模型调用次数（定位成本；P 没有 `read_evidence`，不适用）、第一次调用的提示 token（中位数）。
- **bash 归类**：按管道中第一个认得的命令，分为 `bash:search`（grep、rg）、`bash:read`（cat、head、sed、tail）、`bash:list`（ls、find、wc）、`bash:script`（python、awk）、`bash:git`、`bash:other`。
- **区间**：每题平均值的 95% 区间与配对差的区间，都按题自助抽样，2000 次，种子 20261025。

## 3 核对

- 每题的调用数、input、cacheRead、output 合计，以及各工具的调用次数，都与回答记录相同（966 题，不一致即报错）。
- 三组在每个检查点的题号集合相同。
- 单元测试 `eval/tests/test_read_cost.py` 覆盖 bash 归类、压缩边界、逐步分摊与记账恒等式。
- 手工核对一题（A0 k30 `M-T2-patchtst`，7 次调用、9 次工具调用）：各步的增量、分摊与合计逐项对上。

## 5 对四种解释的判断

- **E-a 粒度：不成立，方向相反。** A3 定位更快（第一次取证据前 2–3 次调用，A0 为 5–7 次），每题的查找调用也更少。MCP 并没有让读者多走步。
- **E-b 输出冗长：部分成立。** A3 单次查找返回是 A0 的 4–5 倍。但在同一批题上，这被更少的步数抵消了（4.1 节）；只在跨论文题上露出来，占 A3 多出部分的 21%。
- **E-c 固定开销：成立，但份额不大。** A3 第一次提示约 7.0–7.2k token，A0 约 4.2–4.4k；固定前缀在跨论文题上占 A3 多出部分的 13%。注意两组的固定开销来源不同：A3 是工具定义，A0 是 `AGENTS.md`。
- **E-d 原生工具：F4-0 无法单独检验。** A0 的库内容与 A3 不同，要靠 A3F（同内容、换接口）。
- **新的一项：`read_evidence` 是最大的一块。** 跨论文题上，A3 读者取证据的次数是 A0 的 1.6 倍，占 A3 多出部分的 37%。它可能来自内容，也可能来自接口，F4-0 分不开：
  - 内容方面：A3 的锚点粒度不同（A3 写者记录：锚点行跨度中位 9 行，A0 为 6 行）；
  - 接口方面：A3 的 search 工具说明与每次 search 结果的开头都提到 `read_evidence`（A3 读者记录第 8 节），可能促使读者更常去取证据。
- 此外，A3 压缩过的会话更多，压缩带来的残差占跨论文题差距的 21%；它是上下文更大的后果，不是独立的来源。

## 6 对 f4 的含义

- A3F 与 A3 的库内容相同，只换读取接口。可以预期 A3F 拿掉 E-b 和 E-c（文件返回小、没有 MCP 工具定义；但 `AGENTS.md` 会进入提示）。`read_evidence` 一项是否下降，正好区分它来自内容还是来自接口：
  - 若 A3F 读者取证据的次数接近 A0，这部分来自 A3 的接口；
  - 若仍接近 A3，则来自 A3 的库内容。
- 读取成本的差别集中在跨论文题，A3F 的报告应把跨论文题单列。
- A3F 冒烟与正式运行时要盯的量：每题查找调用与单次返回、`read_evidence` 次数、第一次提示 token、压缩过的会话数。这些都能直接用 `read_cost` 抽取（加上 `f4:A3F` 即可）。

## 7 局限

- 拆分依赖"思考留在上下文中"的前提（第 2 节）。若不成立，助手输出与工具返回之间的分配会偏，但提示 token 的总量不受影响。
- 压缩过的会话中，残差不归到具体来源；k30 时残差占 A3 提示 token 的 10%、A0 的 8%。
- 两种口径各有缺点：同一批 53 题偏向单篇与简单题，k10 只有 12 道跨论文题；全部题的构成随检查点变化。按题型的比较只在 k30 做。
- 只有一个模型（27B）与一种 agent（pi）。
- P 的成本口径相同，但 P 读全文，它的查找返回包括读原文，与 A3、A0 不完全对应。
