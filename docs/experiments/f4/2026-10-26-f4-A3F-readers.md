## 1 定位

A3F 固定 A3 写入的内容，只换读取路径：把 A3 在每个检查点的库导出为一个只读的 Git 仓库，按 A0 的文件约定呈现，读者像 A0 读者那样用 pi 的默认工具读文件、用 git 看历史，原文只经评测侧的 `read_evidence` 读。库仍是唯一的真实来源，文件树是它的物化视图：派生字段（过时、修订等）由系统算出后写进文件，读者不经文件写回。

- **A3F 对 A3**：库的内容相同，派生字段出自同一份代码，只换读取方式。导出是一种投影，A3 读者能看到的一部分内容（提交的 input、USED 边的 locators 等）没有导出（第 2 节），所以这不是信息完全相同的比较，论文中须写明投影范围。
- **A3F 对 A0**：两套系统的整体比较。读取方式相近，库的内容不同（各自写者建的库）。

## 2 设置

### 2.1 导出（第二版投影，10-25 用户定）

导出由 `tmps/A3F-export.py` 事先生成，运行器只核对、不生成：从空库开始按 A3 快照的 `commits.jsonl` 重放 A3 的提交，每个库提交写成一个 Git 提交（作者、时间与 A3 相同），途经的每个检查点都与快照的 `graph.jsonl` 核对；最后加一个提交写入派生字段，打 `checkpoint-K` 标签。派生字段由 `tmps/A3F-flags.py` 用 A3 读者的冻结代码（`~/pw-lab/frozen/020775c/`）经 CLI 的 `get` 取出（`tmps/A3F-flags/k<K>.json`），脚本不重算任何派生值。

投影只做确定性的取舍与排版，不改写内容、不生成摘要：

- **呈现方式同 A0**：目录结构（`store/nodes/<类>/<id>.yaml`、`store/artifacts/<标题>.md`）、节点 id 文件名、以产物标题为文件名、关系写在起点节点中。不新增按论文组织的目录、名称展开或索引页。
- **提交说明**：库提交的原始 message，末行 `PaperWeave-Commit: commit_<n>`。不放提交的 input（写者交上来的草稿）。
- **省去的字段**：产物的 `_locators`（USED 边的 locators）与 `_uses`（正文已有引用，`task`、`dataset` 等类型字段保留）；节点与产物的 `_edges_in`、`_formed_by`、`_formed_at`（创建者与时间可由添加该文件的第一个提交查到）。
- **保留的状态与次序**：节点为 `id`、`kind`、名称（`name`、`alias`）与所属论文（`paper`）；有 `_anchor_version`、`_revised` 时紧接其后，保留具体原因；其后是证据锚点、正文与关系（次序同 A0）；`_supported_by`、`_opposed_by`、`_used_by` 放在最后，供追查。产物头部为 `type`、`id`、`title`、`abs`；有 `_stale` 时紧接其后；然后是写者头部的其余字段（按文本块原样搬动，次序不变，脚本核对重排前后解析出的内容相同）；正文原样。
