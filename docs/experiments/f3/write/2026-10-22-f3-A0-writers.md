定位：f3 的基线组。A0 是“文件 + Git”方案：写者直接读写共享仓库中的 YAML 记录与 Markdown 产物，经 Git 发布；没有 PaperWeave，也没有它的写入校验。

## 1 目的与定位

A0 检验 E1 的对照条件：没有 PaperWeave 的身份、溯源、版本与过时机制，只有文件、约定与 Git 时，不协调的写者能把库建成什么样、付出多少成本。任务表、材料、写者、模型与预算都与 A3 相同；不同的只有存储方案及其接口。

本次运行的快照供以后：

- 读者在各检查点的仓库上离线作答（A0 读者克隆到检查点标签，可以读、grep 文件与 Git 历史）；
- 在快照上做库层审计，与 A3 对照；
- 给成本账本提供建库一侧的成本。

## 9 已知问题与待办

- **读者未运行**：A0 读者在检查点标签的克隆上离线作答（M2），尚未运行。
- **库层审计未做**：重复率（换了说法的重复）、转录忠实度、产物碎片化（如 5 份按论文拆开的 Note）、过时候选（停在旧版本上的锚点与排行榜行）、build-overlap 会话是重复还是补充。
- **一次提交的代价**：约定要求每个任务一次提交，写者因此把提交留到最后；seq 38 超时，整个任务的改动都没有发布。A3 的写者也常在最后提交，但 A3 的提交是逐次校验、逐次生效的。是否把这一点列为 A0 的固有代价，待库层审计后讨论。
- **上下文溢出**：10 次 `overflow` 压缩，与 A3 记录第 9 节是同一个问题。
- **请求语料外的基线论文**：A0 写者 19 次请求语料外的论文（多是 DLinear、iTransformer 等被引基线），A3 有 17 次类似的拒绝。语料不变，这里只记录。
- **磁盘**：根分区已用 95%，剩余 41G。
