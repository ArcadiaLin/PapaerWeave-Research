## 1 目的

## 4 判分

工具为 `pweval-grade`（`eval/src/pweval/measure/grade_v3.py`），流程如下：

1. **机械判分**：解析 Final answer 段，把方法名、论文名归一到语料中的规范名，按每题的 `scoring` 计分。
2. **送判条目**：机械判不了的条目写入 `grades/pending.jsonl`，包括：
   - 缺 Final answer 段，需从全文抽取答案；
   - 认不出的名称；
   - T7 来源说明等语义子项；
   - 要点题。
3. **判分包**：送判条目打成判分包 `C-v1`（`pweval-grade ref1 packets --groups C --name C-v1`）。
   - 回答以 A1、A2… 编号，不带组名；
   - 编号与运行记录的对照表留在运行目录，不随包发出；
   - 抽取型的题包只给题面、回答和要求的格式，不给参考答案。
4. **判定**：判分包交给合作者，在其本机用 Claude Code 按包内 `CLAUDE.md` 判定（模型未记录），交回 `judgments/`。
5. **导入与出分**：`pweval-grade ref1 import <包> --judge claude-code:collaborator` 逐条核对后导入，然后重新计分。

送判的规模：

- 回答：91 条（主题集）加 6 条（辅助题）。主题集中 109 条完全由机械判出。
- 判定：53 条，其中要点 46 条、抽取 6 条、T7 来源说明 1 条。
- 名称：96 个，71 个论文名判为语料外，22 个方法名归到语料内或语料外的真实方法，2 个判为不是方法，1 个论文名归到语料内。
- 导入核对没有被拒或缺失的条目，导入后没有待判条目。

计分规则中与本组有关的几条：

- 触及安全上限（超时或 `stop=length`）的回答协议分记 0，另存 `content_score`。本组没有这种情况。
- 正文为空记 0。
- 判分前核对运行记录中的题库提交与本机一致且干净。

判分实现中有几处解读尚未与用户确认，本组的分数按这些解读得出：

- T7 按软 F1 给分；
- T3 并列部分命中记 0.5；
- T1 的位置也接受 `cells.csv` 中同值的另一处；
- T8 只在 F1 大于 0 时才判“是否断定某值正确”。

判分者的取舍中，有两处偏宽松：

1. 拼错的方法名归到了正确方法（`Non-hiER`、`Non-hitting` 记为 N-HiTS）；
2. 来历不明的名称（FTime、KITE、TFL、PyRNN）记为语料外的方法，计作答错，而不是作为“不是方法”排除。

两处都不改变本组的结论。

本组只有一位判分者，没有判分一致性的数据。
